랜딩 페이지 만들기

GitHub에 프로젝트를 올리고, Vercel에 연동하여 나만의 랜딩 페이지를 세상에 배포합니다.

GitHub 가입→ Repository 생성→ index.html 작성→ Vercel 연동→ 배포 완료
STEP 1

GitHub 가입 및 Repository 생성

github.com에 접속하여 계정을 만듭니다. (이미 있다면 로그인)

  • 우측 상단 + → New repository 클릭
  • Repository name에 프로젝트 이름 입력 (예: my-landing)
  • Visibility: Public 선택
  • Add a README file 체크 → Create repository
TipRepository 이름은 영문 소문자와 하이픈(-)으로 짓는 것이 관례입니다. 이 이름이 나중에 URL의 일부가 됩니다.
STEP 2

index.html 파일 만들기

Repository 페이지에서 Add file → Create new file을 클릭합니다.

  • 파일 이름: index.html
  • 아래 기본 템플릿을 붙여넣고, 내용을 자유롭게 수정합니다.
<!DOCTYPE html> <html lang="ko"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>내 랜딩 페이지</title> </head> <body> <h1>안녕하세요! 저의 첫 번째 웹페이지입니다.</h1> <p>이 페이지는 곧 멋진 서비스가 될 예정입니다.</p> </body> </html>

하단의 Commit changes 버튼을 눌러 저장합니다.

ChatGPT/Claude 활용AI에게 "OO 서비스 랜딩 페이지 HTML을 만들어줘"라고 요청하면 더 완성도 높은 코드를 받을 수 있습니다. 생성된 코드를 그대로 붙여넣으면 됩니다.
STEP 3

Vercel 가입 및 GitHub 연동

vercel.com에 접속합니다.

  • Sign Up → Continue with GitHub 클릭
  • GitHub 계정 인증을 완료하면 Vercel 대시보드로 이동합니다.
Vercel이란?GitHub에 올린 코드를 자동으로 웹사이트로 만들어주는 무료 배포 서비스입니다. 코드를 수정하고 Push하면 자동으로 반영됩니다.
STEP 4

프로젝트 Import 및 배포

Vercel 대시보드에서 배포를 시작합니다.

  • Add New → Project 클릭
  • Import Git Repository에서 방금 만든 repo 선택 → Import
  • 설정은 기본값 그대로 두고 Deploy 클릭
  • 1~2분 후 빌드가 완료되면 https://my-landing-xxx.vercel.app 형태의 URL이 생성됩니다.
축하합니다!이 URL을 브라우저에서 열면 내가 만든 랜딩 페이지가 전 세계 누구나 볼 수 있는 상태가 됩니다.
STEP 5

코드 수정하고 자동 배포 확인하기

GitHub에서 index.html을 수정하고 Commit하면 Vercel이 자동으로 재배포합니다.

  • GitHub → index.html 파일 클릭 → 연필 아이콘(✏️) 클릭
  • 내용을 수정하고 Commit changes
  • 1~2분 후 같은 URL에 접속하면 변경 사항이 반영되어 있습니다.
핵심 개념이것이 CI/CD (지속적 배포)입니다. GitHub에 코드를 Push하면 Vercel이 자동으로 감지하여 빌드 → 배포까지 처리합니다. 수동으로 서버에 파일을 올릴 필요가 없습니다.

사용성 높이기

Google Stitch로 앱 프로토타입을 디자인하고, Jules를 통해 실제 코드로 변환한 뒤 로컬에서 실행합니다.

Stitch 프로토타입→ Figma 수정→ Jules Export→ GitHub 연동→ 로컬 실행
STEP 1

Google Stitch 접속 및 프로젝트 생성

stitch.withgoogle.com에 접속합니다.

  • 새 → 앱 또는 웹 중 원하는 타입을 선택
  • 우측 모델 선택에서 Fast 모드 선택 — Figma Export 가능
  • 3 Flash 모드는 더 고품질 HTML 디자인 생성
STEP 2

디자인 프롬프트 입력하기

프롬프트 입력창에 원하는 앱의 디자인을 상세히 기술합니다.

You are a senior designer at Apple. Build a pristine, single-page web application for voice recording and transcription that captures the friendly, soft aesthetic of https://www.apple.com/family-sharing/, prioritizing large rounded corners and generous whitespace. Crucially, include a sleek, pill-shaped toggle for language selection (strictly Korean and English, defaulting to Korean) placed prominently near the main action. The core user flow must be: 1) A central, inviting "Record" button in a clean hero section; 2) Upon clicking, transition seamlessly to an active recording state featuring a smooth, organic waveform visualization; 3) When recording stops, immediately generate and display the transcription in the selected language within an elegant, card-style layout with high-contrast typography.
Tip참고할 웹사이트 URL을 넣으면 해당 디자인 톤을 반영합니다. 구체적인 UI 요소(토글, 버튼, 카드)를 명시할수록 결과물이 정확합니다.
STEP 3

디자인 수정 및 Figma로 복사

디자인이 생성되면 상단 메뉴에서 수정합니다.

  • Edit → 채팅에 추가: 특정 화면 수정 요청
  • Edit → 주석 작성: 화면 위에 어노테이션 추가
  • Edit → 테마 수정: 전체 컬러/스타일 변경

수정 완료 후 More → Figma로 복사를 클릭합니다.

STEP 4

GitHub Repository 만들기

github.com에 가입 후 새 Repository를 생성합니다.

  • + New → Repository name 입력 (예: my-voice-app)
  • Visibility: Public → Create repository
STEP 5

Jules 연동으로 코드 Export

jules.google에 접속하여 GitHub 계정을 연동합니다.

  • Try Jules → Connect to GitHub
  • Stitch에서 More → 내보내기 → Format: Jules 선택
  • Repository 선택 → 작업 만들기
한국어 전용 웹 기반 녹음 및 음성 받아쓰기 서비스를 구현한다. 음성 인식은 브라우저 내장 Web Speech API를 사용한다. 사용자가 녹음을 시작하고 종료할 수 있어야 하며, 녹음 완료 후 전체 음성 스크립트를 화면에 표시한다. 변환된 스크립트는 카드(Card) 형식의 데이터로 저장·표시한다. 로그인 및 사용자 인증 기능은 구현하지 않는다.
주의Jules 무료 플랜은 일일 세션 제한이 있습니다. 중요한 작업은 미리 계획하세요.
STEP 6

로컬에서 프로젝트 실행하기

# GitHub에서 프로젝트 다운로드 (현재 터미널 위치에 폴더가 생깁니다) # 바탕화면에 받으려면 먼저: cd Desktop git clone https://github.com/[내아이디]/[레포이름].git # 프로젝트 폴더로 이동 cd [레포이름] # Jules가 만든 브랜치로 전환 git checkout feature-voice-rec-service-xxxxx # 패키지 설치 후 실행 npm install npm run dev

브라우저에서 http://localhost:3000으로 접속하여 확인합니다.

사전 준비npm 명령어를 사용하려면 Node.js가 먼저 설치되어 있어야 합니다. nodejs.org에서 LTS 버전을 다운로드하여 설치하세요. 설치 후 터미널에서 node -v를 입력해 정상 설치를 확인할 수 있습니다.
STEP 7

Vercel로 배포하기

로컬에서 잘 돌아가는 걸 확인했으면, 이제 누구나 접속할 수 있도록 웹에 배포합니다.

먼저, main 브랜치를 만들어줍니다 (1번만 하면 됩니다).

# 현재 코드를 main 브랜치로 만들기 git checkout -b main # GitHub에 올리기 git push -u origin main
왜 이걸 해야 하나요?Jules는 코드를 feature-xxx라는 이름의 브랜치에 만들어줍니다. Vercel은 기본적으로 main 브랜치를 배포하기 때문에, 위 명령어 2줄로 main을 만들어주는 겁니다.
API 키가 필요한가요?이 프로젝트의 음성 받아쓰기는 브라우저 내장 Web Speech API를 사용합니다. 별도의 API 키나 백엔드 설정 없이 무료로 작동하며, Chrome/Edge는 Google 음성 인식 엔진, Safari는 Apple 음성 인식 엔진을 사용합니다. 브라우저에 따라 인식률이나 동작(침묵 시 끊김 등)에 차이가 있을 수 있습니다. 더 높은 인식률이 필요하면 OpenAI Whisper 등 외부 AI 모델 연동도 가능합니다.

그 다음, Vercel에서 배포합니다.

  • vercel.com 접속 → GitHub 계정으로 로그인
  • Add New Project → 내 repo 선택 → Import
  • Deploy 클릭 → 빌드 완료 후 URL 자동 생성
  • 생성된 URL로 접속하면 내 서비스가 웹에 공개됩니다

통제권 가져가기

기획 단계에서 놓치기 쉬운 관리자 페이지를 Replit으로 구현하여 운영 가능한 서비스 구조를 만듭니다.

누락 기능 파악→ PRD에 반영→ Replit에 요청→ 관리자 페이지 구현
STEP 1

기획 단계에서 놓치기 쉬운 것 인식하기

바이브 코딩으로 빠르게 만들면 사용자 화면에만 집중하기 쉽습니다. 실제 운영에는 다음이 필수입니다.

  • 관리자 페이지 — 콘텐츠 등록/수정/삭제
  • 대시보드 — 사용자 통계, 트래픽 모니터링
  • 권한 관리 — 일반 사용자 vs 관리자 분리
키즈GPT 사례YouTube Studio 같은 콘텐츠 관리 화면을 구상했지만, 실제로는 API doc에서 직접 JSON을 입력하는 방식으로 운영해야 했습니다. 기획 단계에서 관리자 기능을 빠뜨리면 추가 개발 비용이 발생합니다.
STEP 2

PRD에 관리자 기능 추가하기

기존 PRD에 관리자 관련 요구사항을 명시적으로 추가합니다.

현재 서비스에 관리자 페이지를 추가해줘.

관리자 기능 요구사항:
- 관리자 로그인 (간단한 비밀번호 방식)
- 콘텐츠 CRUD (생성/조회/수정/삭제) 대시보드
- 콘텐츠 목록을 테이블로 표시 (제목, 상태, 날짜)
- 새 콘텐츠 추가 시 폼 UI 제공
- 사용자 화면과 관리자 화면은 별도 라우트로 분리 (/admin)
STEP 3

Replit에서 관리자 모드 구현 요청

Replit에서 기존 프로젝트를 열거나 새 프로젝트를 생성합니다.

  • 채팅창에 PRD 내용을 붙여넣고 구현을 요청
  • Replit Agent가 관리자 라우트, 인증 로직, CRUD UI를 자동 생성
  • 부족한 부분은 추가 프롬프트로 보완
STEP 4

관리자 페이지 테스트 및 검증

구현된 관리자 페이지를 다음 기준으로 검증합니다.

  • 관리자 로그인이 정상 작동하는가?
  • 콘텐츠 추가/수정/삭제가 사용자 화면에 즉시 반영되는가?
  • 일반 사용자가 /admin에 접근할 수 없는가?
  • 데이터 오류 시 적절한 에러 메시지가 표시되는가?
핵심서비스를 "운영 가능한 구조"로 만들려면 사용자 화면과 관리자 화면을 동시에 설계하세요. 이것이 바이브 코딩에서 주도권을 가져가는 핵심입니다.

대화형 UX 적용하기

웹툰 데이터에 Gemini API 챗봇을 붙이고, GitHub → Vercel로 배포하여 대화형 서비스를 완성합니다.

웹툰 데이터→ PRD 작성→ Antigravity 개발→ Gemini API→ Vercel 배포
STEP 1

대화형 UX의 가치 이해하기

기존 서비스가 one-time 인터랙션이었다면, AI 에이전트를 붙이면 ongoing 관계로 진화합니다.

  • 아마존 루퍼스 — 브래키팅 문제를 AI 대화로 해결, 연간 반품비용 $400억 절감
  • 네이버 웹툰 설효림 챗봇 — 열람 회차수 97%↑, 매출 44%↑
STEP 2

웹툰 데이터 다운로드

강의 자료에서 제공하는 네이버 웹툰 JSON 데이터를 여기에서 다운로드합니다.

{ "title": "개같이 탈출", "author": "갬자", "thumbnail": "https://image-comic.pstatic.net/...", "story": "살아남으라고? 나는 자그만 말티즈란 말이야!...", "genre": ["드라마", "생존", "힐링", ...], "ageRating": "Unknown" }
STEP 3

ChatGPT로 PRD 작성하기

현재 내가 갖고 있는 웹툰 디비야.
이거 바탕으로 리스트 형식으로 웹툰 디스플레이하고,
내가 관심있는 웹툰을 찾는 챗봇도 붙일거야.
웹툰 검색해서 매칭하고 대사 생성하는건 gemini-2.5-flash-lite 쓸거야.
기능 중심으로 간결하게 기획안 써줘. 코드는 쓰지마

생성된 PRD를 prd.md 파일로 저장합니다.

STEP 4

Gemini API 키 발급받기

aistudio.google.com/api-keys에 접속합니다.

  • API 키 만들기 클릭 → 프로젝트 선택 → 키 복사
주의API 키를 코드에 직접 넣지 마세요. 반드시 .env.local 파일에 저장합니다.
STEP 5

Antigravity에서 개발 시작하기

프로젝트 셋업 후, AI 코딩 에이전트에게 다음과 같이 요청합니다.

prd.md 기반해서 데이터베이스에 저장된 웹툰을 리스트로 보여주고 (썸네일 및 주요 정보 포함), 챗봇을 통해서 내 취향의 웹툰을 찾을 수 있는 챗봇 기능을 구현한다.

데이터는 webtoons.json 활용하고 DB는 변경하지 않는다.
gemini-2.5-flash-lite 모델로 사용한다.
다음 Gemini Key는 .env.local에 저장한다.
GEMINI_API_KEY=***
모델 선택Gemini 모델 종류와 특징은 Gemini API 모델 문서에서 확인할 수 있습니다. 비용과 속도를 고려해 적절한 모델을 선택하세요.
  • Next.js 프로젝트 구조, 웹툰 리스트 UI, 챗봇 컴포넌트가 자동 생성
  • 오류 발생 시 에러 로그를 복사해서 다시 요청
STEP 6

GitHub에 Push하기

# Git 초기화 & 커밋 cd /Users/[내이름]/Desktop/[프로젝트폴더] git init git add . git commit -m "first commit" # GitHub repo 연결 & Push git remote add origin https://github.com/[내아이디]/[레포이름].git git branch -M main git push -u origin main
PAT 토큰 만들기GitHub → Settings → Developer settings → Personal access tokens → Generate new token (classic) → repo 전체 체크 → Generate → ghp_... 토큰을 Push 시 Password로 입력합니다.
STEP 7

Vercel로 배포하기

vercel.com에서 GitHub 계정으로 로그인합니다.

  • Add New Project → GitHub repo 선택 → Import
  • Environment Variables에 GEMINI_API_KEY 추가
  • Deploy 클릭 → 빌드 완료 후 URL 자동 생성
배포 완료Vercel은 GitHub와 자동 연동되어, 이후 Push할 때마다 자동 배포됩니다.

코워크 맛보기

사용자가 원하는 결과만 설명하면 클로드가 알아서 복잡한 업무를 수행하는 AI 에이전트. 파일 정리, 문서 작성, 영수증 정리, 데이터 분석 등 귀찮은 업무를 자동화합니다.

클로드 코워크 파일 관리 브라우저 자동화 커넥터 연동 루틴 자동화 스킬 만들기
STEP 1

클로드 코워크란?

클로드 코워크는 사용자가 원하는 결과만 자연어로 설명하면, 클로드가 알아서 복잡한 업무를 수행하는 AI 에이전트입니다.

  • 파일 정리, 문서 작성, 영수증 정리, 데이터 분석 등 귀찮은 업무 자동화
  • 브라우저 자동화로 웹 리서치와 문서 생성까지 한 번에
  • 커넥터를 통해 Gmail, Slack, Notion 등 외부 서비스와 연동
같이 해봐요!아래 Case들을 직접 따라하면서 코워크의 강력한 기능을 체험해 보세요.
STEP 2

Case 1: 파일 관리

데스크탑 파일 정리, 검색, 분석을 자연어로 요청할 수 있습니다.

이 폴더에 있는 이미지 파일들을 image 폴더로 만들어서 다 넣어줘.
이 폴더 안에 있는 영수증들을 분석하고 엑셀 파일로 만들어줘
Tip파일 관리 작업은 클로드가 로컬 파일 시스템에 직접 접근하여 수행합니다. 폴더 생성, 파일 이동, 데이터 추출 및 변환까지 자동으로 처리됩니다.
STEP 3

Case 2: 브라우저 자동화

유튜브 댓글 분석, 경쟁사 리서치, 문서 자동 생성 등을 수행합니다.

'OOO'에 대해서 조사해줘. 다음 출처를 참고해서 나에게 pdf, docx, pptx 파일로 보고서를 작성해줘. (병렬로 수행해라)
병렬 수행여러 형식의 보고서를 동시에 생성하도록 요청하면, 클로드가 병렬로 작업을 처리하여 시간을 절약합니다.
STEP 4

Case 3: 커넥터 이용하기

외부 서비스와 연동하여 업무를 자동화합니다.

커넥터 설정 방법:

(+) > 파일이나 커넥터 추가 > 커넥터 > 커넥터 관리 > 커넥터 둘러보기

지메일 커넥터 – 최신 이메일 확인 및 요약

최신 이메일을 확인하고 중요한 내용을 요약해줘.

슬랙 커넥터 – 대화록 분석 및 공유

슬랙 general 채널에 최근 일주일간의 모든 대화록을 분석하고, pdf로 저장한 뒤 그걸 다시 슬랙으로 보내줘
방금 보낸 요약을 노션에도 송부해줘
Tip커넥터를 연결하면 Gmail, Slack, Notion 등 다양한 서비스 간의 데이터를 자유롭게 주고받을 수 있습니다.
STEP 5

Case 4: "예정됨" 기능으로 루틴 업무 자동화

기존 작업에서 /schedule을 입력해서 루틴 업무를 자동화할 수 있습니다.

/schedule 매일 아침 9시에 새로운 AI 소식을 뉴스레터로 만들어서 나에게 슬랙으로 보내줘
활용 예시매일 유튜브에 신규로 올라오는 AI 뉴스를 요약하여 뉴스레터로 받아볼 수 있습니다. 반복적인 정보 수집과 공유를 완전히 자동화하세요.
BONUS

별책부록: 클로드 스킬

특정 작업을 반복적으로 사용할 때 스킬로 템플릿화하여 활용합니다.

  • 매번 같은 프롬프트를 복사-붙여넣기 하지 말자
  • Skill은 Claude Code의 업무 레시피입니다
  • 반복 작업을 모듈화해서 클로드에게 부여하는 패키지
특정 유튜브 url을 넣으면 링크드인과 스레드 글을 한 번에 제작해서 슬랙에 공유하는 스킬 만들어줘. 스킬명: youtube-to-content

Skill 폴더 구조

my-skill/ ├── SKILL.md # 필수: 스킬의 본체. 메타데이터 + 지시사항 ├── scripts/ # 선택: 실행할 코드 (Python, Bash 등) ├── references/ # 선택: 참고 문서, 교안, 데이터 └── assets/ # 선택: 템플릿, 리소스 파일
TipSKILL.md만 있으면 스킬이 됩니다. 나머지 폴더는 필요할 때 추가하세요.

Skills란?
Skills는 Claude가 할 수 있는 작업을 확장합니다. SKILL.md 파일을 지침과 함께 생성하면 Claude가 이를 자신의 도구 모음에 추가합니다. 관련이 있을 때 자동으로 사용하거나, /skill-name으로 직접 호출할 수 있습니다.

번들 Skills (기본 제공)

/batch <instruction> # 코드베이스 전체에서 대규모 변경을 병렬로 조율 /claude-api # Claude API 참조 자료 로드 /debug [description] # 현재 세션 문제 해결 /loop [interval] <prompt> # 프롬프트를 주기적으로 반복 실행 /simplify [focus] # 코드 재사용, 품질, 효율성 검토 후 수정

첫 번째 Skill 만들기 (3단계)

1. Skill 디렉토리 생성

mkdir -p ~/.claude/skills/explain-code

2. SKILL.md 작성 – YAML frontmatter(메타데이터) + markdown(지침)

--- name: explain-code description: Explains code with visual diagrams and analogies. --- When explaining code, always include: 1. Start with an analogy 2. Draw a diagram (ASCII art) 3. Walk through the code step-by-step 4. Highlight a gotcha

3. 테스트 – 자연어로 물어보거나 /explain-code src/auth/login.ts로 직접 호출

Skill을 저장하는 위치 = 사용 범위

Enterprise 관리 설정 # 조직의 모든 사용자 Personal ~/.claude/skills/ # 내 모든 프로젝트 Project .claude/skills/ # 이 프로젝트만 Plugin <plugin>/skills/ # 플러그인이 활성화된 위치
우선순위같은 이름의 skill이 여러 위치에 있으면: Enterprise > Personal > Project 순으로 우선합니다.

Frontmatter 주요 필드

--- name: my-skill # 표시 이름 (/slash-command가 됨) description: 무엇을, 언제 # Claude가 자동 로드 시기 판단에 사용 argument-hint: [filename] # 자동완성 시 표시되는 힌트 disable-model-invocation: true # Claude 자동 실행 방지 (수동 전용) user-invocable: false # / 메뉴에서 숨기기 (배경 지식용) allowed-tools: Read, Grep # 허용할 도구 제한 context: fork # 격리된 subagent에서 실행 agent: Explore # subagent 유형 지정 ---

인수 전달하기

$ARGUMENTS로 전체 인수를, $0, $1 등으로 개별 인수에 접근합니다.

# /fix-issue 123 → "Fix GitHub issue 123..." Fix GitHub issue $ARGUMENTS following our coding standards. # /migrate-component SearchBar React Vue Migrate the $0 component from $1 to $2.

동적 컨텍스트 주입

!`command` 구문으로 skill이 로드되기 전에 shell 명령어를 실행하고 결과를 삽입합니다.

## Pull request context - PR diff: !`gh pr diff` - PR comments: !`gh pr view --comments` - Changed files: !`gh pr diff --name-only`

호출 제어 요약

(기본값) # 사용자 O, Claude O disable-model-invocation: true # 사용자 O, Claude X (배포, 커밋 등) user-invocable: false # 사용자 X, Claude O (배경 지식)

지원 파일 추가

SKILL.md를 500줄 이하로 유지하고, 상세한 참조 자료는 별도 파일로 분리합니다.

my-skill/ ├── SKILL.md # 주요 지침 (필수) ├── template.md # Claude가 채울 템플릿 ├── examples/ │ └── sample.md # 예제 출력 └── scripts/ └── validate.sh # Claude가 실행할 스크립트

문자열 치환 변수

$ARGUMENTS # 전달된 모든 인수 $ARGUMENTS[N] / $N # N번째 인수 (0부터 시작) ${CLAUDE_SESSION_ID} # 현재 세션 ID ${CLAUDE_SKILL_DIR} # SKILL.md가 있는 디렉토리 경로
TipSkill이 트리거되지 않으면 description의 키워드를 확인하세요. 너무 자주 트리거되면 disable-model-invocation: true를 추가하세요.
